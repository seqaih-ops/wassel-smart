# Wassel Smart | وصّل بذكاء

إعداد: **عبدالله الصقيه**

## الفكرة
تقدير احتمال تأخر التوصيل قبل تنفيذه، ومقارنة الوضع الحالي بسائق بديل ومسار بديل يحدد المستخدم بياناتهما. النتيجة تقدير من نموذج تعلم آلة فعلي؛ ليست قاعدة نقاط يدوية ولا خدمة خرائط.

## امتداد المختبرات
- Lab 1: نفس موضوع التوصيل وهدف Delayed ومدخلات Distance_Km وDriver_Orders وTraffic_Level.
- Lab 2: خاصيتا Distance_Traffic وOrders_Traffic وخط المعالجة.
- Lab 3: Random Forest مرجعي وGradient Boosting مضبوط بالتحقق المتقاطع.
- إضافة المشروع: بيانات أوسع، مقارنة سيناريوهات وواجهة عربية. لا تدعي هذه الإضافة استيفاء تعليمات Lab 4 التي لم تصل بعد.

## البيانات والمنهجية
3,000 سجل اصطناعي مولّد ببذرة 42؛ ليس امتدادا لثمانية سجلات حقيقية. احتمالات التوليد تعتمد على المسافة وعدد الطلبات والازدحام وتفاعلاتها مع ضوضاء عشوائية، ثم تولد النتائج بسحب Bernoulli. هذا يفترض علاقات تعليمية ولا يثبت وجودها في الواقع. كل المدخلات مفترضة متاحة وقت إسناد الطلب.

النطاق: مسافة 1–50 كم، طلبات صحيحة 0–10، ازدحام 1/2/3. التقسيم الطبقي: 2,400 تدريب، 600 اختبار مستقل. البحث في 8 تركيبات على 3 طيات تدريب بمقياس Average Precision (AP). إحصاءات المعالجة تتعلم داخل الطيات. تُقيَّم النماذج على الاختبار بعد الضبط، دون استخدام الاختبار لاختيار النموذج المنشور أو حد القرار. حد التصنيف ثابت 0.5. يبقى النموذج المنشور مدربا على مجموعة التدريب فقط حتى تتطابق نتائجه مع التقييم.

StandardScaler باق للاستمرارية وللنموذج اللوجستي، وليس ضروريا للأشجار. تعويض القيم المفقودة موجود في خط التدريب؛ الواجهة تطلب مدخلات مكتملة ضمن النطاق. AP ليس مساحة شبه منحرف تحت المنحنى. انخفاض الاحتمال في سيناريو افتراضي لا يثبت أثر التغيير سببيا. أهمية الخصائص مبنية على خفض عدم النقاء ولا تمثل أسبابا أو اتجاهات تأثير.

## التشغيل
1. افتح Wassel_Smart_Project.ipynb في Google Colab وشغّل الخلايا بالترتيب؛ أو ثبت المتطلبات ثم شغّل `python project/train.py` من جذر الحزمة.
2. للواجهة المحلية: شغّل `python -m http.server 8000 --directory dist` من جذر الحزمة، ثم افتح http://localhost:8000.
3. بعد إعادة التدريب، انسخ `project/outputs/model.json` و`project/outputs/metrics.json` إلى `dist/` لتحديث الواجهة؛ النموذج الموجود جاهز للاستخدام.
4. تحقق من تطابق Python والمتصفح عبر `node project/test_export.js` (يتطلب Node.js).

تتضمن الحزمة واجهة محلية وNotebook والكود وCSV للبيانات والمقاييس والنموذج المُصدّر. الواجهة تعمل دون API خارجي؛ تحمل الأشجار المدربة وتنفذها داخل المتصفح. CSV المقارنة قابل للتنزيل من الواجهة. لا توجد معلومات شخصية أو اتصالات بأنظمة توصيل فعلية.

## ماذا تعني النتيجة؟
فئات العرض: منخفض <30%، متوسط 30% إلى <60%، مرتفع ≥60%؛ حدود تعليمية وليست سياسة تشغيل. التصنيف مستقل: متأخر عند ≥50%. المقارنة تحافظ على مسافة وازدحام الطلب عند تبديل السائق، وعلى طلبات السائق عند تبديل المسار. قد يتعادل السيناريو أو يصبح أسوأ؛ لا يفرض النظام تحسنا.

## القيود والتطوير
النتائج تقيس بيانات اصطناعية فقط؛ لا توجد معايرة تشغيلية للاحتمالات. قبل أي استخدام فعلي نحتاج سجلات حقيقية، تعريف تأخر واضح مرتبط بالوقت الموعود، فصل زمني للاختبار، منع ظهور السائق أو الرحلة نفسها عبر التقسيم عند اللزوم، تحقق من معايرة الاحتمالات، وتقييم تكلفة الإنذارات الخاطئة والتأخر الفائت. لم يضف المشروع بيانات وقت تجهيز أو طقس لم يزوّد بها المستخدم.
